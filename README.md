# KITSUNE · демонстрационная витрина

Работающая мобильная витрина восьми реальных украшений. Браузерное демо проходит весь путь: выбор → запрос → обработка администратором → актуальный результат у клиента.

## Запуск

Нужен Node.js 22.13 или новее. Внешних npm-зависимостей нет.

```powershell
cd kitsune-demo
npm start
```

Откройте [http://localhost:4173](http://localhost:4173). Чтобы остановить сервер, нажмите Ctrl+C.

Проверки:

```sh
npm run check
npm test
```

Браузерное демо также работает на любом статическом HTTPS-хостинге: опубликуйте содержимое `dist/`. Для обычного показа не нужны бот, токен, база или сборка. `index.html` следует открывать через HTTP(S), не через `file://`.

Публичное демо GitHub Pages: [artemdiscipline.github.io/kitsune-demo/](https://artemdiscipline.github.io/kitsune-demo/). Вход в ChatGPT или GitHub для просмотра не нужен. Здесь опубликован только frontend в режиме `demo`; backend и бот требуют отдельного запуска. Локальное демо, версия на Sites и GitHub Pages имеют отдельные хранилища браузера.

## Как показать владельцу студии за две минуты

1. Откройте витрину, нажмите на накрутку №14501338. Увеличьте фото, посмотрите материал и отметьте «Нужна помощь с размером».
2. Добавьте её в запрос. Через «Добавить ещё» выберите кластер №14495089. Предварительная сумма — 4 000 ₽.
3. Нажмите «Заполнить тестовыми данными», затем «Проверить запрос». Посмотрите состав и нажмите «Создать тестовый запрос».
4. Запомните номер. Нажмите «Посмотреть как администратор».
5. Для накрутки выберите «Наличие подтверждено», для кластера — «Нужно уточнение». Добавьте комментарий и нажмите «Нужно уточнение» или «Сохранить изменения».
6. Переключитесь в «Клиент». В том же запросе видны частичное подтверждение и комментарий. Обновите страницу: данные сохранятся.

Демо ничего не отправляет студии. В нём нет выдуманных запросов: список заполняется только после создания через форму. Данные хранятся в `localStorage` этого браузера. При очистке данных сайта запросы демо удалятся. Настоящие контакты для показа не нужны.

Администратор также может предложить замену из каталога. Клиент отдельно принимает или отклоняет предложение. Исходная позиция и её цена в запросе сохраняются.

## Каталог и проверка

Все восемь точных карточек VK проверены в браузере 23 октября 2026 года. Для каждой сохранены соответствующее реальное фото, цена и указание «Материал: титан ASTM F-136». Товар с турмалином назван так в самом источнике; дополнительные характеристики камня не приписаны.

Проверенные цены: 1 500, 2 200, 1 600, 2 500, 3 000, 3 000, 4 000 и 4 000 ₽ в порядке списка из задания. Ссылки, дата проверки и сведения о происхождении фото находятся в `catalog-audit.json`, вне пользовательского интерфейса.

Для **каждой** из позиций 14501338, 14501335, 14501329, 14495089, 14495080, 14495073, 14495040 и 14488779 ещё нужно подтвердить:

- размеры и резьбу;
- комплектацию, в том числе основание для накруток;
- фактические остатки;
- существование конкретных вариантов.

Новые фотографии для этих восьми карточек не требуются: загружено по одному фото соответствующего товара. Подтверждённых дополнительных фотографий и вариантов не добавлено. Общая доступность карточки VK не считается подтверждением наличия. Число в поле артикула — стабильный ID карточки VK, не выдуманный внутренний артикул студии.

Фильтра по материалу нет: подтверждённый материал у всех восьми товаров одинаковый. Работают поиск по названию, ID и материалу, фильтры типа и цены. Локальные шрифты и фотографии не зависят от доступности VK при показе.

## Подключение Telegram

Сейчас Telegram **фактически не подключён**. Токен и тестовый администратор не заданы. Сообщения настоящей студии не отправлялись. Подготовлены минимальный бот, серверный API, серверное хранилище SQLite и один интерфейс для обоих режимов.

1. Создайте отдельного тестового бота через [@BotFather](https://t.me/BotFather), командой `/newbot`. Полученный токен храните только на сервере.
2. Разместите **весь проект** на Node.js-сервере с постоянным диском и HTTPS. Он сам отдаёт и `dist/`, и `/api`. Например, `https://your-own-domain.example`. Статической публикации GitHub Pages для backend и бота недостаточно.
3. Скопируйте `.env.example` в `.env` и заполните переменные:

| Переменная | Назначение |
| --- | --- |
| `APP_MODE=telegram` | Включает авторизованный серверный режим. |
| `BOT_TOKEN` | Токен отдельного тестового бота. В frontend не передаётся. |
| `MINI_APP_URL` | HTTPS-адрес **этого Node.js-сервера**, без завершающего `/`. Здесь задаётся адрес Mini App и кнопок бота. |
| `ADMIN_TELEGRAM_IDS` | Числовые Telegram ID администраторов через запятую. Не `@username`. |
| `TEST_ADMIN_CHAT_ID` | Личный числовой ID тестового администратора проекта. Должен входить в `ADMIN_TELEGRAM_IDS`. Не контакт студии. |
| `DATABASE_PATH` | Путь к SQLite на постоянном диске. Один файл для сервера и бота, если процессы запускаются вместе. |
| `PORT` | HTTP-порт сервера; по умолчанию 4173. |
| `HOST` | Для внешнего хостинга обычно `0.0.0.0`, локально `127.0.0.1`. |
| `INIT_DATA_TTL_SECONDS` | Максимальный возраст подписанных данных Telegram; по умолчанию 3600 секунд. |

4. Тестовый администратор должен сам открыть личный чат с тестовым ботом и нажать `/start`. Его числовой ID можно получить из поля `message.from.id` входящего update тестового бота; не отправляйте токен в сторонние сервисы.
5. Запустите два постоянно работающих процесса с одним окружением:

```sh
npm start
npm run bot
```

6. При запуске бот регистрирует `/start`, устанавливает кнопку меню через `setChatMenuButton` и отправляет на `/start` приветствие с кнопкой `web_app`. В [@BotFather](https://t.me/BotFather) также можно настроить Main Mini App или `/setmenubutton` на тот же `MINI_APP_URL`. Бот использует long polling; для одного токена нужен один процесс и отсутствие webhook другого приложения.
7. Откройте витрину **через кнопку бота**. Обычный браузер в режиме `telegram` не проходит авторизацию. Клиент и администратор на разных устройствах должны войти со своими Telegram ID в один и тот же бот и открыть один сервер.

Сервер проверяет HMAC подпись и срок `initData` по [официальному механизму Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). `initDataUnsafe` не используется для идентификации. Права администратора проверяются на сервере; демонстрационного переключателя ролей в подключённом режиме нет. Клиенту доступны только его запросы, администратору — отдельный список.

Цена и свойства поступают из серверного каталога. Переданная клиентом цена игнорируется. Созданный запрос содержит снимок товара. SQLite хранит запросы, версии изменений, ключи защиты от повторной отправки и очередь уведомлений. Повтор с тем же ключом возвращает исходный запрос. Устаревшие правки администратора не перетирают новые.

Уведомления о новых запросах отправляются только в `TEST_ADMIN_CHAT_ID`. Без этой переменной сервер сохраняет запросы, но уведомления не отправляет. Сбой Telegram не отменяет сохранённый запрос: уведомление остаётся в очереди, повторяется каждые 30 секунд, максимум 50 попыток. Очередь сохраняется при перезапуске. При неопределённом сетевом ответе Telegram уведомление может повториться; сам запрос не дублируется.

Развёртывание реального сервера, обмен между двумя физическими устройствами, реальный `/start` и доставка сообщений в Telegram **не проверены**: для этого требуются ваши настройки и отдельный тестовый чат. Локальные API-тесты используют синтетически подписанные данные и подменённый транспорт Telegram, без отправки сообщений.

## Структура

```text
dist/
  index.html, app.js, style.css  — интерфейс без этапа сборки
  config.json                  — статическая публикация работает как demo
  storage.js                   — браузерное хранилище и ошибки сохранения
  shared/catalog.js            — только данные реальных товаров
  shared/model.js              — единая модель и правила запросов
  assets/                      — соответствующие фото и локальный Manrope
server/
  index.mjs                    — HTTP API, права, сохранение и очередь
  telegram.mjs                 — проверка initData и вызовы Bot API
  store.mjs                    — SQLite
  bot.mjs                      — /start, кнопки и long polling
tests/                         — модель, хранилище, подпись и API
catalog-audit.json              — ссылки и результаты проверки источников
VERIFICATION.md                 — что фактически проверено
```

Код не добавляет оплату, доставку, запись, лояльность, сроки резерва и автоматические рекомендации по совместимости.

## Публикация GitHub Pages

Workflow `.github/workflows/pages.yml` проверяет код и тесты, затем публикует только `dist/` при push в `main`. Права Pages настроены через GitHub Actions. Фото, шрифты, скрипты и настройки используют относительные пути и работают в подкаталоге `/kitsune-demo/`.
